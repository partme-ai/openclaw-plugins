# OpenClaw 2026.11.3 Upgrade Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将插件宿主基线迁移到 OpenClaw 2026.11.3，消除已删除的 SDK 导入，恢复 wecom 的安装态加载，并发布 27 个 Gateway 插件和共享 message-sdk。

**Architecture:** 保留现有插件、渠道配置、消息和投递语义；仅迁移公开 SDK 入口、版本元数据和相关门禁。以官方 `v2026.11.3` 的 package exports 和源码为契约，本地 research/openclaw 用于定位，不能替代安装态验收。

**Tech Stack:** TypeScript、Node 24.18.0、pnpm 9.0.0、Vitest、node:test。

**Spec:** 本文的目标与全局约束为本轮增量规格；通用约定沿用 `spec/PLUGIN_SPEC.md`。2026.9.6 的历史计划和验收记录保持原样。

## Global Constraints

- 开发宿主固定 `2026.11.3`，peer/install/compat 下限为 `2026.11.3`；插件版本不随宿主自动变化。
- 保留现有 Python 缓存删除。以 2026.11.3 为最低宿主，使用最新稳定版 2026.11.4 交叉验证。仅操作隔离的验收 Gateway；按 2026-11-16 用户授权向 npm 发布全部 28 个包。
- 不使用私有源码入口、伪造声明或关闭类型检查绕过 SDK 不兼容。
- 安装、锁文件、编译、测试和最终包加载均需真实结果；源码检查不能冒充运行时通过。

## Review Focus

- WebSocket 与 Webhook 入口均不能残留 channel-message 导入。
- 微信命令鉴权、媒体根和文件锁必须沿用宿主安全 API。
- 发布包必须包含 wecom 的 build/compat 元数据。
- 旧宿主和旧 E2E 报告不得满足新基线门禁。
- npm 网络失败时，不手写 integrity、依赖解析或安装成功记录。
