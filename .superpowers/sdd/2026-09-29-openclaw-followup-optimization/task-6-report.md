## Fact path and scope

`message-sdk` writes `delivery.started` after the durable send-start record and emits one final `delivered`/`ambiguous` settlement after journal settlement or deferred broker confirmation; retry facts are separate. Router emits bounded retry, final failed/ambiguous, and current DLQ depth facts from its durable dispatcher. Memory and OpenMem emit completed search duration from their search `finally` paths. Each producer uses the public OpenClaw `emitDiagnosticEvent(log.record)` bus with logger namespace `partme.delivery-recall.v1`; Tracing and Prometheus subscribe through host diagnostics, independently of bundled SDK module instances. Diagnostics must be enabled. The bus is asynchronous and may drop facts, so metrics are best-effort observations, not an ACK ledger.

Tracing validates the versioned schema, fixed channel/outcome/plugin fields and `id_[a-f0-9]{24}` identities before exporting `delivery.started`, `delivery.settlement`, `delivery.retry`, `delivery.dlq`, and `memory.recall` spans. Delivery start and settlement share the same SHA-256 pseudonymous ID. Duplicate hook registrations in one host process claim a diagnostic sequence once per logical OTLP endpoint/header scope or file directory; distinct sinks each receive it, while log backends use object identity. A process-wide ticket retains claims for one event until all listener callbacks finish, limited to 1024 active events, 128 sinks per event, and 30 seconds. Full capacity or timeout drops the span. A claim precedes asynchronous export, so failure at the chosen exporter can lose the fact; it does not guarantee fallback through another registration. Prometheus accepts only metric-bearing event kinds, never identity labels, and exposes the most recently observed durable DLQ depth, retry/final settlement counters, recall duration, diagnostics enabled status, host async queue loss, and DLQ observation age/freshness. Router republishes its durable DLQ depth every 30 seconds while running (two in-memory locked snapshots per minute per instance, no new disk reads), and stops the unref timer at shutdown. Stop invalidates each registration generation and unsubscribes before draining its accepted work.

The host's public `log.record` bus has no verifiable emitter provenance. Any enabled plugin can forge a schema-valid envelope; schema validation limits fields, metric cardinality, and sensitive values but cannot authenticate the source. Only trusted plugins should be installed. O6 metrics and spans are not audit or delivery ACK authority, and scrape authorization does not prevent internal spoofing.

## RED and GREEN

- Post-review RED: Router telemetry `snapshot()` rejection after durable replay, final dead-letter commit, and startup initialization respectively rejected a committed replay, skipped terminal bookkeeping, and leaked a writer lease. GREEN: all three observations are fail-open while store failures remain visible in Router health/logs. A restarted metrics subscriber initially lost the DLQ gauge without another Router transition; the 30-second Router republish restores it, and shutdown cancels its timer. Prometheus exporter reset clears the gauge and observation timestamp; a later fact restores both. With Router explicitly enabled in Gateway config, missing or older-than-90-second DLQ observations degrade telemetry health. With no Router entry or fact, the optional Router substatus is unavailable/unknown without degrading overall telemetry health.
- Post-review RED: a delayed Router `start()` could resume after `stop()`, retain the writer lease and install a timer; a stopped status probe could reacquire that lease. GREEN: lifecycle generations cancel stale starts, stop waits for initialization before closing, a concurrent new start waits for old stop, and stopped status uses its cached snapshot. Prometheus service reload tests confirm Router enabled/disabled health follows each new `ctx.config`, rather than stale registration config.
- Post-review RED: two Tracing registrations with different backend objects exported only to the first backend. A real six-plugin E2E then found two OTLP backend objects targeting the **same Collector** both exported the same fact. The first bounded sink cache also re-exported when 65 other sinks intervened between same-sink listeners for one event. GREEN: logical OTLP endpoint plus hashed sorted header scope or file directory identifies a sink; event tickets preserve claims through all callbacks, including a delayed provider after 2050 later diagnostics. Different sink scopes export independently, same sink exports once while the ticket is live. Timeout and capacity tests lock drop behavior. Log backends retain per-object claims. The privacy/schema validation path is unchanged.
- RED: deferred SDK result lost its Agent run ID; `channel-dispatch.test.ts` expected the hashed run ID and failed. GREEN: callback captures the initial run ID; repeated confirmation does not duplicate final settlement. Ack-pending restart recovery has no persisted run ID and does not invent one.

- RED: two live Tracing registrations exported two spans for one host diagnostic event. GREEN: one export for the same event; after stopping the first registration, the second still exports a subsequent event. Existing concurrent stop/start and restart tests remain green.
- GREEN: forged `log.record` with raw IDs, invalid labels, or extra attributes is rejected; 10,000 distinct IDs keep metric series bounded; telemetry emitter exceptions preserve the business result.
